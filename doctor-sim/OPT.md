# doctor-sim 性能优化建议

本文档列出若干可能的性能优化方向，供后续按需实施。当前 `doctor-sim` 是
解释型模拟器，主循环每条指令都会进行取指、解码、执行、设备 tick、中断检查等，
因此性能优化的核心是减少每条指令的固定开销，并让热点路径更紧凑。

## 1. 降低主循环固定开销

当前 `cpu_run()` 在每条指令后都会：

- 调用 `input_poll()`
- 调用 `device_tick_all()`
- 调用 `get_next_intr()`

即使没有任何输入、设备不需要计时、也没有中断挂起，这些调用仍然发生。

建议：

- 将 `input_poll()` 改为每 N 条指令轮询一次（如每 1024 条），或使用
  `select`/`poll`/非阻塞读取 + 事件驱动。
- 为每个设备增加“是否需要 tick”的快速标志；空闲设备可跳过 tick。
- 当 `cpu->halted == true` 且没有挂起中断时，可以进入低功耗等待，
  而不是继续空转 tick。
- 将中断检查合并进设备 tick：只有设备 tick 后可能产生新中断时才调用
  `get_next_intr()`。

## 2. 解码/执行热点优化

当前 `decode()` 和 `execute()` 使用较大的 `switch` 分支，且每条指令都重新解析。

建议：

- 使用 **跳转表 / 函数指针表** 代替 `switch`，减少分支预测失败。
- 在 GCC/Clang 下可考虑 **computed goto / labels as values** 实现直接线程化解释器。
- 对重复执行的代码块（循环）增加 **trace cache / 解码缓存**：
  - 第一次解码后缓存指令长度、操作数、操作码；
  - 相同地址再次执行时直接使用缓存结果。
- 对常见指令（`LET`、`MOV`、`ADD`、`PUSH`、`POP`、`JMP` 等）做专用快速路径，
  避免进入通用操作数处理。

## 3. 内存访问与边界检查

`mem.h` 中的 `mem_range_ok()` 每次访问都做 64 位范围比较；虽然已内联，
但在每条 `LR/ST/PUSH/POP` 等指令中仍可能多次调用。

建议：

- 在 `execute()` 开头把 `dbase/dlimit/cbase/climit` 缓存到局部变量，
  减少反复从 `cpu->sys` 读取。
- 使用 `__builtin_expect` 标记“正常路径不越界”，提高分支预测。
- 为常见尺寸（1/2/4 字节）提供专用快速路径，将范围检查合并成单次无符号比较：
  ```c
  if ((uint32_t)(addr - dbase) > (uint32_t)(dlimit - dbase - bytes))
      goto fault;
  ```
- 如果性能优先且安全策略允许，可增加 `-DDOCTOR_FAST_MEM` 编译选项，
  在关闭 MPU/物理边界检查的场景下跳过部分检查（仅用于测试/演示）。

## 4. 寄存器与局部变量访问

`*op2reg(cpu, reg)` 每次都返回 `&cpu->regs[reg]`，指针追踪较浅但仍有调用/解引用。

建议：

- 在 `execute()` 中使用 `uint32_t *regs = cpu->regs;` 局部指针，避免多次
  `cpu->regs` 访存。
- 将最热门的寄存器访问（`A`、`B`、`C`、`S`、`F`）直接映射到局部变量，
  在指令边界同步回 `cpu->regs`。
- 将 `Decoded_instr` 中的操作数编码提前翻译为寄存器索引/立即数，减少执行期转换。

## 5. 设备层优化

当前 `device_tick_all()` 遍历所有设备，每个设备即使无事可做也会执行 tick。

建议：

- 给 `Device` 增加 `bool active` / `uint64_t next_tick`，只有活动设备才进入 tick。
- 对 PIT/UART/KBC/DISK 等设备，将“是否有待处理事件/中断”作为快速标志，
  无事件时 tick 几乎为零成本。
- 将设备链表改为数组或按端口索引，减少 `device_find()` 的线性查找。
- 如果主机性能允许，可以把设备 tick 批量到“每条指令一次”改为“每 N 条指令一次”，
  并用累计周期数补偿设备计时。

## 6. 编译选项与构建优化

当前 `Makefile` 使用 `-O2 -g`。可以尝试：

- `-O3`
- `-march=native`（仅在目标主机明确时使用）
- `-flto`（链接时优化）
- `-fomit-frame-pointer`
- 对 release 构建关闭 `-g` 或使用 `-g3` 仅调试构建
- 使用 PGO（Profile-Guided Optimization）收集热点后重新编译

## 7. 更进一步的架构级优化

如果后续需要数量级提升，可以考虑：

- **二进制翻译 / 动态重编译**：将 DOCTOR 指令翻译为宿主机器码，热点基本块
  缓存并直接执行。
- **块解释器**：把多个 DOCTOR 指令组成基本块，一次调度执行整块，减少主循环开销。
- **并行设备模拟**：若多核可用，可将设备 tick 与 CPU 执行流水化（需处理确定性）。
- **快照/记录重放**：对确定性模拟场景，可将设备 tick 与 CPU 指令按周期解耦，
  用更大的时间片批量推进。

## 8. 建议的落地顺序

1. 先做低风险改动：主循环减少 `input_poll` 频率、设备 tick 快速跳过、局部变量缓存。
2. 再做解码/执行跳转表与指令快速路径。
3. 最后考虑 trace cache、块解释器或二进制翻译。

> 优化时请始终保持 `doctor-sim` 的确定性语义：中断优先级、设备时序、异常触发顺序
> 不能因优化而改变。
